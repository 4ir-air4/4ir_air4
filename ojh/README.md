# AERO INSIGHT 프로젝트 설명서 (ojh)

작성일: 2026-11-16 · 온라인 문서판: https://claude.ai/artifact/UR8AaeR8FciARJbaJthSoS

AERO INSIGHT는 실시간 항공기 관측, 공항 월별 통계, 사진 분석(YOLO), AI 도우미를 하나의 Streamlit 앱으로 묶은 항공 데이터 대시보드입니다. 이 문서는 ojh가 맡은 기능 다섯 가지가 어떤 데이터로, 어떤 방법으로, 왜 그렇게 동작하는지 설명합니다. 인천 지연 예보·모델 비교 등 ldh 메뉴는 팀원 작업이라 여기서는 다루지 않습니다.

## 전체 구성

다섯 기능은 모두 `streamlit run app.py` 하나로 열리는 같은 앱 안에 있고, 데이터 수집 → 모델 학습 → 화면 표시 순서로 이어집니다.

| 기능 (메뉴) | 무엇을 하나 | 데이터 | 핵심 기술 |
| --- | --- | --- | --- |
| 실시간 지도 | 지금 하늘에 떠 있는 전 세계 항공기를 지도에 표시, 클릭하면 사진·경로·실제 궤적 | OpenSky Network 실시간 상태(5분 갱신), Planespotters 사진, adsbdb 노선 | folium 지도, OpenSky OAuth2, 로컬 궤적 프록시 |
| 교통량 예측 | 5분 뒤 전 세계 비행 중 항공기 수 예측, 모델 4개 비교 | 직접 만든 수집기가 5분마다 쌓은 항공기 수 + 날씨, BTS 과거 운항 샘플 | 시간순 교차검증, Optuna 튜닝, Linear·RandomForest·XGBoost·LightGBM |

| 계류장 혼잡도 | 공항 사진에서 비행기·차량·사람을 세어 혼잡 등급 | 사용자가 올린 CCTV·위성 사진 | YOLO11(COCO), YOLO11-OBB(DOTA), 조각 탐지 + 중복 제거 |
| AI 도우미 에어로 | 모든 페이지 오른쪽 아래 채팅. 데이터 질문, 항공권 조회, 사진 설명 | 대시보드 표, SerpApi Google 항공권, Tavily 검색 | Gemini(gemini-3.1-flash-lite) 도구 호출, Claude 대체 경로 |

## 실시간 지도

지금 하늘에 있는 전 세계 항공기(보통 5,000~7,000대)를 OpenSky Network에서 받아 지도에 표시합니다. 파일은 `ojh/live_app.py`입니다.

**데이터 받기**

1. `.streamlit/secrets.toml`의 OpenSky 클라이언트 ID·비밀키로 OAuth2 토큰을 받습니다.
2. `/states/all`(전 세계, extended=1)을 불러 항공기별 위치·고도·속도·방향·기체 분류를 받습니다. 한 번에 4크레딧을 쓰고, 10분 동안은 다시 부르지 않도록 저장해 둡니다.
3. 조회가 실패하면 마지막으로 받은 데이터(`ojh/data/cache/opensky_states_last.json`)를 보여줍니다.

**화면**

- 상단 숫자: 위치 확인 항공기, 비행 중, 지상 대수.
- 마커 모양: 기체 분류(경량·소형·중형·대형·A380급·헬리콥터 등)에 따라 아이콘 크기가 다르고, 진행 방향으로 회전하며, 고도에 따라 색이 바뀝니다. OpenSky 분류가 없는 기체는 기체 DB(`aircraft_database.csv`)의 기종 코드로 보완합니다.
- 마커를 누르면: Planespotters의 기체 사진, adsbdb의 출발·도착 노선(점선, 추정 경로), OpenSky `/tracks/all`의 실제 이동 궤적(실선, 고도 색)을 보여줍니다.

**구현에서 주의한 점**

- 궤적은 OpenSky 인증이 필요해 브라우저가 직접 부를 수 없습니다. 그래서 앱이 `127.0.0.1:8765`에 작은 프록시 서버를 띄워 토큰을 붙여 대신 조회합니다.
- OpenSky는 한 비행을 여러 조각으로 나눠 저장하므로, 지상·저고도 지점을 기준으로 지금 비행에 해당하는 조각만 이어 붙입니다.
- 수천 개 마커를 빠르게 그리려고 FastMarkerCluster를 씁니다.

## 실시간 수집기와 교통량 예측

'지금 값'과 최근 흐름으로 5분 뒤 전 세계 비행 중 항공기 수를 예측하며, 학습 모델 4개가 모두 '직전 값 그대로' 기준선보다 오차가 약 30% 작습니다.

**1. 수집 (`ojh/data_collector.py`)**

- 5분마다 OpenSky 전 세계 상태를 받아 위치가 있는 항공기 수를 적고, 항공기 위치의 중앙점 날씨(Open-Meteo: 기온·강수·구름·바람·돌풍)와 공휴일 여부를 함께 저장합니다.
- 저장 파일: `ojh/data/raw/aircraftlive_counts.csv` (2026-11-04부터, 약 3,000행). 한 번에 4크레딧, 하루 약 1,150크레딧을 씁니다.
- 수집기는 앱과 따로 돌아야 하므로 터미널에서 `python ojh/data_collector.py`를 켜 둡니다.

**2. 학습 (`ojh/models/train.py`)**

- 데이터 두 가지: '현재(실시간 수집)'와 '과거(BTS TranStats 샘플)'를 각각 학습합니다.
- 입력값(피처): 지금 값, 5·10·15·30·60분 전 값, 최근 5분 변화량, 15분·60분 이동평균, 30분 표준편차, 시간·요일·월(sin/cos), 날씨, 공휴일.
- 정답(타깃): 5분 뒤 값. 30분 이하의 짧은 빈칸은 직전 값으로 메웁니다.
- 나눔: 시간 순서를 지켜 맨 뒤 15%는 최종 테스트로 남기고, 앞부분은 시간순 교차검증(최대 5개 구간)으로 평가합니다. 미래 정보가 학습에 섞이지 않게 하려는 것입니다.
- 튜닝: Optuna로 모델마다 최대 30번(3분) 하이퍼파라미터를 찾고, 기본값을 첫 시도로 넣어 튜닝 결과가 기본값보다 나빠지지 않게 했습니다.

**3. 결과 (현재 데이터, 시간순 교차검증 평균)**

| 모델 | MAE (대) | RMSE (대) | MAPE (%) |
| --- | --- | --- | --- |
| Linear Regression | 40.4 | 64.4 | 0.51 |
| Random Forest | 40.9 | 63.3 | 0.53 |
| XGBoost | 42.4 | 65.1 | 0.54 |
| LightGBM | 44.2 | 67.5 | 0.57 |
| 기준선 (직전 값) | 61.3 | 87.2 | 0.77 |

항공기 수는 5분 사이에 크게 변하지 않아 선형 모델도 충분히 잘 맞힙니다. 수집 기간이 2주 미만이라 결과는 더 쌓일수록 달라질 수 있습니다. 화면에서는 모델을 골라 예측 곡선을 보고, [재학습] 버튼으로 최신 데이터로 다시 학습할 수 있습니다.

## 공항 수요 예측

미국·유럽·영국·한국 공항 551곳의 월별 이용객을 학습해 향후 12개월을 예측하며, 선정 모델(LightGBM)의 12개월 예측 오차(WAPE)는 5.0%로 '작년 같은 달' 기준선(7.2%)보다 작습니다.

**1. 데이터 모으기 (`ojh/fetch_airports.py`)**

| 지역 | 출처 | 받는 방법 |
| --- | --- | --- |
| 미국 | BTS T-100 | 내려받은 CSV를 `ojh/data/airport_demand/input/t100`에 둔다 |
| 유럽 | Eurostat | API로 자동 수집 |
| 영국 | UK CAA 공항 통계(Table 09) | 월별 CSV를 코드가 찾아 자동으로 내려받음 |
| 한국 | 항공정보포털(에어포탈) 시계열 통계 | 포털이 화면에 쓰는 조회 요청을 코드가 직접 보내 연도별 엑셀 18번 받기를 대신함 |
| 공통 | 나라별 실질 GDP 성장률 | 연도별 표 |

네 출처를 하나의 표(공항·날짜·이용객·출처, 약 24만 행, 2000-01~2026-10)로 합칩니다. 이력이 36개월보다 짧은 공항은 빼서, 이스탄불처럼 최근 생긴 대형 공항까지 포함해 551곳을 분석합니다.

**2. 모델 설계 (`ojh/models/train2.py`)**

- 정답(타깃): 이용객 수 자체가 아니라 '이번 달이 직전 12개월 평균보다 얼마나 많은가'의 로그 비율입니다. 애틀랜타(연 1억 명)와 지방 공항(연 수만 명)을 같은 모델이 배울 수 있게 규모를 없앤 것입니다.
- 입력값: 지난 달들의 로그 비율, 3·6개월 평균, 변동성, 작년 대비 변화, 공항 규모, 계절(월 sin/cos), 코로나 기간(2020-03~)과 회복 기간(~2022-12) 표시, GDP 성장률, 지역.
- 나눔: 시점 기준 학습 | 검증 24개월 | 테스트 최근 12개월.
- 평가: 한 달 앞 예측과 함께, 앱의 연간 곡선과 같은 방식인 12개월 재귀 예측(예측값을 다음 달 입력으로 다시 쓰기)을 검증 구간의 세 시점에서 평가합니다.
- 모델 선정 기준은 MAPE 대신 WAPE(전체 절대오차 합 ÷ 전체 실제 이용객 합)입니다. MAPE는 이용객이 거의 없는 달이 있는 작은 공항 하나에 크게 흔들리기 때문입니다.
- 공항마다 마지막 실측 달이 다르므로(유럽은 나라별로 보고가 늦음), 예측은 각 공항의 마지막 실측 다음 달부터 시작합니다. 12개월 넘게 데이터가 끊긴 공항(폐쇄 등)은 예측에서 뺍니다.

**3. 결과 (WAPE, 낮을수록 좋음)**

| 모델 | 검증 12개월 재귀 (선정 기준) | 테스트 한 달 앞 | 테스트 12개월 재귀 |
| --- | --- | --- | --- |
| LightGBM (선정) | 5.00% | 3.37% | 5.03% |
| XGBoost | 5.05% | 3.41% | 5.20% |
| Random Forest | 5.09% | 3.42% | 5.37% |
| 기준선 (작년 같은 달) | 7.23% | 5.03% | 5.04% |
| Linear Regression | 14.79% | 7.81% | 12.64% |

테스트 12개월 재귀에서는 기준선과 거의 같아, 안정적인 해에는 '작년 같은 달'도 강한 예측값이라는 점을 함께 보여줍니다.

**4. 화면 (`ojh/_3_airport_tab.py`)**

- 개요: 분석 공항 수(전체 공항 수 포함), 데이터 기간, 학습 행 수를 지역별 설명과 ⓘ 도움말로 보여줍니다.
- 모델 비교와 공항별 예측 vs 실제 그래프.
- 시뮬레이터: 공항과 GDP 성장률을 바꾸며 연간 이용객 곡선이 어떻게 달라지는지 봅니다.
- 향후 12개월 예상 이용객 TOP 10.
- 공항 순위 레이스: 실제와 예측을 이어 붙여 공항 순위가 달마다 바뀌는 모습을 지역 색으로 애니메이션합니다.

## 계류장 혼잡도 (YOLO)

공항 사진을 올리면 YOLO가 비행기·차량·사람을 찾아 세고, 그 수에 가중치를 곱한 혼잡 점수로 네 단계 등급을 매깁니다. 파일은 `ojh/_5_apron_tab.py`입니다.

**1. 사진 종류에 맞는 모델 고르기**

| 사진 종류 | 모델 | 학습 데이터 | 찾는 대상 |
| --- | --- | --- | --- |
| 지상·CCTV (옆이나 비스듬히 찍은 사진) | YOLO11 m(기본)·s·n | COCO, 일상 사진 80종 | 비행기, 버스, 트럭(지상조업차), 승용차, 오토바이, 사람 |
| 위성·항공 (바로 위에서 본 사진) | YOLO11m-OBB | DOTA, 항공사진 15종 | 비행기, 헬리콥터, 대형·소형 차량 (기울어진 박스) |

두 모델 모두 Ultralytics가 미리 학습해 둔 모델을 그대로 씁니다(추가 학습 없음). 각도가 다른 사진에 다른 모델을 쓰는 이유는, 모델이 학습한 사진과 비슷한 각도에서 가장 잘 맞히기 때문입니다.

**2. 비행기·차량을 찾는 과정**

1. 긴 변이 2048px보다 큰 사진은 줄입니다(속도).
2. 전체 사진을 640과 1280 두 해상도로 탐지합니다. 가까운 큰 비행기는 640에서, 멀리 있는 작은 대상은 1280에서 잘 잡힙니다.
3. 사진을 640px 조각으로 25%씩 겹치게 잘라 조각마다 따로 탐지합니다. 넓은 사진을 통째로 넣으면 작은 비행기가 몇 픽셀로 뭉개져 사라지기 때문입니다. ('세밀하게'를 고르면 480px로 자르고 2배로 키워 찾습니다.)
4. 합치기: 조각 테두리에 걸쳐 잘린 박스와 조각을 거의 다 덮는 거대 박스는 버립니다. 남은 박스는 같은 묶음(비행기/차량/사람)끼리 겹침 제거(NMS)를 하고, 더 확실한 박스 안에 60% 이상 들어가는 박스도 지웁니다. 같은 비행기를 일부만 잡은 박스, 같은 차를 승용차와 트럭으로 두 번 잡은 박스가 이렇게 하나가 됩니다.

**테스트 결과 (신뢰도 기준 0.2)**

| 사진 | 예전 (YOLO11n, 조각 없음) | 지금 (YOLO11m + 조각) | 실제 |
| --- | --- | --- | --- |
| 인천공항 전경 (비스듬한 항공사진) | 비행기 0대 | 비행기 17대, 약 11초 | 수십 대 (게이트에 붙은 작은 기체 포함) |
| 하와이 공항 계류장 | 비행기 16대(중복 포함), 차량 3대 | 비행기 13대(오탐 1), 차량 26대, 약 10초 | 비행기 약 12대 |

**3. 혼잡 등급**

등급은 두 가지 방식 중 하나로 매깁니다. 사진에 보이는 자리(주기장) 수가 있으면 ① 점유율 방식, 없으면 ② 점수 방식을 씁니다.

**자리 수는 AI(Gemini)가 사진을 보고 추정합니다.** YOLO는 '주기장'을 찾지 못하고(학습 데이터에 없음), 공항 전체 주기장 수는 사진에 일부만 나오면 분모로 쓸 수 없습니다(예: 인천 전경 사진에 13대가 보여도 13/120은 맞지 않음). 그래서 사진마다 **보이는 자리 수**가 필요한데, 사람이 넓은 사진에서 세기는 어렵습니다.

- 각 사진 옆의 **🤖 AI로 자리 수·장소 알아보기** 버튼을 누르면 Gemini가 탑승교, 바닥 표시선, 줄지은 비행기 사이 빈틈을 보고 다음을 알려줍니다.
  - 주기장에 서 있는 비행기 수 (유도로에서 움직이는 비행기는 뺌)
  - 보이는 자리 수 (빈자리 포함, 원격 주기장 포함)
  - 장소 (공항·터미널 이름)와 그 공항 전체 주기장 수 (AI 지식 기반 참고값, 계산에는 쓰지 않음)
- 점유율은 AI가 센 '서 있는 비행기 ÷ 보이는 자리'로 계산합니다. AI 값이 틀렸으면 '이 사진에 보이는 자리 수' 칸을 직접 고칩니다.
- 모델은 gemini-3.8-flash → 3.7-flash → 3.6-flash → 3.1-flash-lite 순서로 시도합니다. 무료 등급에서 flash는 하루 20번(3.1-flash-lite는 500번)이라, 사용량 초과·혼잡 오류가 나면 다음 모델로 넘어갑니다. lite로 추정하면 정확도가 낮다고 표시합니다.
- 같은 사진의 AI 결과는 디스크에 저장해서 다시 묻지 않습니다(앱을 다시 켜도 유지). 버튼을 눌렀을 때만 요청하므로 하루 한도를 아낄 수 있습니다.

모델 선택은 정답을 아는 사진 3장으로 Gemini·Gemma 모델 14개를 비교해서 정했습니다(2026-11-17).

| 사진 | 정답 (사람이 셈) | gemini-3.8-flash | gemini-3.1-flash-lite |
| --- | --- | --- | --- |
| 두바이 터미널 (위성사진) | 비행기 16 / 자리 20 | 16/20, 17/21 (약 20초) | 26/36 (약 2초) |
| 하와이 터미널 | 비행기 약 12 / 자리 약 14 | 12/12 | 10/12 |
| 뮌헨 터미널 2 위성동 | 비행기 7 / 자리 20개 이상 | 7/21 | 7/13 |

- flash 계열은 '생각'을 거쳐 유도로의 비행기를 빼고 세서 정확하지만 느리고(20~60초) 하루 20번입니다. lite 계열은 2~3초로 빠르지만 비행기가 빽빽한 사진에서 많이 셉니다.
- 공항 전체를 아주 넓게 찍은 사진(인천 전경)은 같은 모델도 물을 때마다 자리 수가 크게 달라졌습니다(81~151개). 터미널 하나 정도가 보이는 사진이 가장 정확합니다.

탐지 결과는 저장해 두므로 자리 수나 가중치를 바꿔도 YOLO를 다시 돌리지 않고 등급만 바로 다시 계산합니다. 여러 장을 비교할 때 판단 방식이 사진마다 다르면 값 대신 등급 단계로 비교합니다.

**① 주기장 점유율 (자리 수가 있을 때, 권장)**

점유율 = 서 있는 비행기 수 ÷ 사진에 보이는 자리 수 (AI 추정이 있으면 AI가 센 비행기 수, 없으면 YOLO 탐지 수)

| 등급 | 점유율 | 예 (주기장 30개) |
| --- | --- | --- |
| 여유 | 40% 미만 | 비행기 11대 이하 |
| 보통 | 40% 이상 70% 미만 | 비행기 12~20대 |
| 혼잡 | 70% 이상 90% 미만 | 비행기 21~26대 |
| 매우 혼잡 | 90% 이상 | 비행기 27대 이상 |

- 큰 공항은 원래 비행기와 차량이 많아서, 대수만 세면 여유로운데도 '매우 혼잡'으로 나옵니다. 예를 들어 게이트 30개에 비행기 10대, 차량 40대인 사진은 점수 방식으로는 92.5점(매우 혼잡)이지만, 점유율로는 33%(여유)입니다. 그래서 공항 크기를 반영할 수 있도록 '얼마나 찼나'를 기준으로 삼았습니다.
- 차량은 등급에 넣지 않고, 비행기 1대당 차량이 4대 이상이면 '지상조업 활발'로 따로 표시합니다.
- 비행기가 주기장 수보다 많으면 유도로·활주로의 비행기까지 셌거나 주기장 수를 적게 넣었을 수 있다고 안내합니다.

**② 혼잡 점수 (자리 수를 모를 때: AI 버튼을 누르지 않았거나 실패한 경우)**

혼잡 점수 = 비행기 수 × 5 + 차량 수 × 1 + 사람 수 × 0.5

| 등급 | 점수 | 예 |
| --- | --- | --- |
| 여유 | 10 미만 | 비행기 1대 + 차량 몇 대 |
| 보통 | 10 이상 25 미만 | 비행기 3~4대가 지상조업 중 |
| 혼잡 | 25 이상 45 미만 | 비행기 5~8대 + 차량 다수 |
| 매우 혼잡 | 45 이상 | 비행기 9대 이상, 또는 비행기와 차량이 모두 많음 |

이렇게 정한 이유:

- 비행기 한 대는 주기장 하나를 차지하고 급유차·수하물 차량·토잉카 등 여러 대를 불러오므로 혼잡에 미치는 영향이 가장 커서 5점을 줍니다.
- 차량은 계류장 동선을 직접 붐비게 하므로 1점, 사람은 작업자가 많아도 공간을 덜 차지해 0.5점입니다.
- 구간 경계(10·25·45)는 표의 예처럼 '비행기 몇 대 + 차량'이 눈으로 보기에 여유·보통·혼잡으로 느껴지는 수준에 맞춘 제안값입니다. 실제 공항 운영 기준에서 가져온 숫자는 아닙니다.
- 이 방식은 공항 크기를 모르기 때문에 큰 공항일수록 혼잡하게 나오기 쉽습니다. 주기장 수를 알면 ① 점유율 방식을 쓰는 게 정확합니다.
- 카메라마다 한 화면에 담기는 면적이 달라, 가중치는 화면의 '탐지·혼잡도 기준 조정'에서 바꿀 수 있습니다. 시간대별 CCTV를 여러 장 올리면 사진끼리 점수를 비교하는 표와 막대그래프가 나오므로, 같은 카메라의 시간대별 비교에 가장 잘 맞습니다.

## AI 도우미 에어로

모든 페이지 오른쪽 아래 말풍선 버튼으로 여는 채팅이며, AI가 직접 답을 지어내지 않고 대시보드 표·항공권·검색 도구를 불러 확인한 값으로 답합니다. 파일은 `ojh/_4_ai_chat_tab.py`입니다.

**1. 동작 순서 (도구 호출)**

1. 질문과 함께 안내문(역할·규칙·오늘 날짜), 도구 설명서, 지금까지의 대화를 AI에 보냅니다.
2. AI가 바로 답할지, 어떤 도구를 어떤 값으로 부를지 정합니다. AI는 도구를 직접 실행하지 못하고 요청만 합니다.
3. 우리 코드가 도구를 실행해 결과를 돌려주고, AI는 그걸 보고 또 도구를 부르거나(최대 8번) 답을 씁니다.
4. 답 아래 '조회한 내용'을 펼치면 어떤 도구를 어떤 조건으로 불렀는지와 출처 링크가 나옵니다.

**2. 도구**

| 도구 | 하는 일 | 쓰는 질문 |
| --- | --- | --- |
| list_tables / query_table | 공항 월별 이용객, 12개월 예측, 모델 비교, GDP, 실시간 수집 표를 조건·묶기·정렬해 최대 50행 조회 (읽기 전용, 임의 코드 실행 없음) | 2025년 이용객 TOP 5 공항은? |
| get_ldh_summary | 팀원 분석 카테고리의 결과 요약(summary.json) | 인천 도착편 지연 예측 요약 |
| search_flights | SerpApi로 Google 항공권 검색 결과 조회 (항공사·편명·출발·도착·소요·경유·원화 가격·보통 가격대) | 다음 주 금요일 인천→도쿄 편도 최저가는? |
| web_search | Tavily 검색으로 최신 소식·규정 찾기 | 인천공항 수하물 규정은? |

기종·공항 상식은 AI가 알고 있는 지식으로 답하고, 사진을 올리면(최대 3장) 기종·항공사 도장 등을 설명합니다.

**3. AI 선택과 비용**

- `secrets.toml`에 `GEMINI_API_KEY`가 있으면 Gemini(gemini-3.1-flash-lite, 무료 등급), 없고 `ANTHROPIC_API_KEY`만 있으면 Claude를 씁니다.
- 무료 한도: Tavily 월 1,000회, SerpApi 월 250회(같은 검색을 1시간 안에 다시 하면 횟수에 들어가지 않음). Gemini 무료 등급은 입력 내용이 Google 제품 개선에 쓰일 수 있어 채팅 창에 안내합니다.

**4. 작은 모델을 안정적으로 쓰기 위한 장치**

- 항공권 질문 강제: '항공권·비행기표·항공편·최저가·편도·왕복' 같은 말이 있으면 코드가 첫 단계에서 search_flights를 반드시 부르게 합니다. 안내문만 바꿨을 때는 작은 모델이 가끔 웹 검색으로 빠져 대략적인 답을 했기 때문입니다.
- 날짜 기본값: '지금·당장'은 오늘, 날짜가 없으면 7일 뒤. '가장 빠른'은 소요 시간 짧은 순으로 조회합니다.
- 작은 공항: 결과가 없으면 가까운 큰 공항을 함께 넣어 다시 조회합니다(예: 시우다드델에스테 AGT → AGT, IGU, ASU).
- 항공편 표는 코드가 그립니다: AI가 표를 만들면 매번 칸이 달라져(출발·도착이 빠지는 등) 조회 결과로 출발·도착·소요·가격·경유·항공사·편명 표를 항상 같은 모양으로 붙이고, AI 답은 가장 빠른·싼·일찍 출발하는 편 요약만 합니다.
- 왕복 결과에는 가는 편 시각만 있어, 오는 편 시각을 지어내지 않도록 결과와 안내문에 명시했습니다.

## 실행 방법과 파일 구조

저장소 최상위에서 패키지를 설치하고 키를 넣은 뒤, 수집기와 앱을 각각 터미널에서 켭니다.

**1. 준비**

1. `pip install -r requirements.txt` (GPU가 없으면 torch는 CPU 판을 먼저 설치하면 더 가볍습니다)
2. `.streamlit/secrets.toml`에 키를 넣습니다. 값은 반드시 따옴표로 감쌉니다. 이 파일은 git에 올라가지 않습니다.

| 키 | 쓰는 곳 | 없으면 |
| --- | --- | --- |
| OPENSKY_CLIENT_ID, OPENSKY_CLIENT_SECRET | 실시간 지도, 수집기 | 익명 조회(한도가 적음) |
| GEMINI_API_KEY | AI 도우미 | 도우미가 키 안내만 보여줌 |
| TAVILY_API_KEY | AI 도우미 웹 검색 | 검색 없이 답함 |
| SERPAPI_API_KEY | AI 도우미 항공권 조회 | 항공권 조회 없음 |

**2. 실행**

```
python ojh/data_collector.py              # 실시간 수집기 (켜 두기)
streamlit run app.py                      # 앱
python ojh/fetch_airports.py              # 공항 월별 데이터 갱신 (필요할 때)
python ojh/models/train.py                # 교통량 모델 학습
python ojh/models/train2.py               # 공항 수요 모델 학습
```

**3. ojh 폴더**

| 파일 | 역할 |
| --- | --- |
| `live_app.py` | 실시간 지도 화면, OpenSky 인증, 궤적 프록시 |
